# 整理已有工作区

[返回首页](../README.md) · [安装与维护](installation.md)

当前版本：`v0.3.0`。本文适用于已经用了很久的目录：根目录堆着几百个文件和用途不明的文件夹，并且在各个 AI 客户端里留有旧对话。

整理分成两条线，都只在用户主动要求时进行：

| | 整理工作区 | 旧对话接续 |
| --- | --- | --- |
| 做什么 | 一次性把已有内容归入规划好的主题，之后的新内容沿用同一套规划 | 整理之前产生的对话继续使用时，找到文件的新位置并接着工作 |
| 谁触发 | 用户说“整理这个工作区” | 用户在那个对话里说“这是整理前的旧对话” |
| 能否移动文件 | 按用户确认的计划移动 | 默认不移动；确需移动时在该对话中逐项取得授权 |
| 依据 | 本文的“AI 整理协议” | 工作区内的 `.agents/old-chats.md` |

安装 Kit 本身不会整理任何内容。整理之后新开的对话是普通对话，隔天或换窗口继续也不会被当成旧对话。

## 整理如何保证安全

- **先计划，后移动。** AI 把“原路径 → 新路径”写成计划文件，脚本校验通过并经用户确认后才执行。
- **移动有记录。** 每一项移动都写入 `.agents/moves.tsv`。任何对话都能用 `where <旧路径>` 查到文件现在的位置。
- **可以撤销。** `move --undo` 把最近一批移动原样移回。
- **不覆盖，不删除。** 目标已存在时拒绝执行；重复或疑似无用的文件只列出，由用户决定。
- **清点不靠通读。** 脚本 `scan` 输出文件数、体积、最近修改日期和标记，并在脚本内部检查哪些文件写死了工作区的绝对路径，只报告文件名不输出内容。AI 只在名称无法判断时读取少量文件的开头。
- **不碰凭据。** 配置、密钥、会话类文件只按名称判断归属，不打开，也不纳入任何搜索。

边界：脚本只移动文件，不修改文件内容。文件之间写死的绝对路径、虚拟环境和 IDE 的最近项目不会自动修正；整理不是备份，重要内容请先自行备份。

## AI 整理协议

本节写给执行整理的 AI。只有用户明确要求整理、改造或重新规划已有工作区时才执行；遇到需要用户决定的事项，停在该步骤询问。

### 1. 准备

- 目标未安装 Kit 或版本低于 `v0.3.0` 时，先按 [安装与维护](installation.md) 安装或升级，并用 `scan --write-allowlist` 登记现有根目录条目。
- 告诉用户最终的绝对路径，并建议在开始前备份；确认没有其他 AI 会话或程序正在写这些文件。
- 询问用户已有的规划偏好：例如按项目还是按类型分组、哪些目录不能动。用户没有偏好时使用本协议的默认做法。

### 2. 清点

在目标根目录运行（解释器依次尝试 `python3`、`python`、`py -3`）：

```text
python .agents/tools/workspace_doctor.py scan --limit 500
python .agents/tools/workspace_doctor.py scan <子目录>
```

- 第一条列出根目录的全部条目；根目录文件超过上限时调大 `--limit`。
- 第二条只用于名称看不出用途的目录，查看它的下一层。
- 仍无法判断时，读取该目录的说明文件或少量文件的开头。不递归列目录，不通读文件。
- 标记含义：`git` 仓库；`project` 含项目清单；`agent` 含 AI 规则或技能文件（`AGENTS.md`、`.agents/`、`SKILL.md` 等）；`env` 含虚拟环境；`cache` 缓存目录；`abspath` 有文件写死了本工作区的绝对路径，输出会附上几个文件名。
- 是否写死绝对路径以 `abspath` 标记为准，不自行对工作区做全文搜索：搜索工具常默认跳过隐藏目录，也容易漏掉 JS、JSON 字符串中双写反斜杠的写法，还会把文件内容带进上下文。
- 根目录下的零散文件也会带 `abspath` 标记。它们常引用工作区里的其他条目，移动其中任何一方都可能使引用失效；计划摘要中要写出这类文件和它引用的条目（可读取该文件中含路径的那几行确认）。
- 凭据类文件只按名称判断，不打开：`config.json`、`.env`、`*.key`、`*.pem`、`credentials*`、`secrets*`、`session*`、`cookie*`、`token*`，以及所在目录名为 `.cache` 而用途不明的文件。已经看到的密钥、cookie 或令牌不写进任何输出、计划、入口或笔记，只提醒用户该文件含敏感内容。

### 3. 规划

把每个根目录条目归入以下三类之一：

| 类别 | 适用 | 处理 |
| --- | --- | --- |
| 移入主题 | 零散文件、普通资料目录、已结束的项目 | 移到 `work/YYYY-MM-DD-主题/` 下；已有主题与之属于同一件事时并入该主题 |
| 原地保留并登记 | 嵌套工作区与技能目录（`agent` 标记）、Git 仓库、带 `env` 或 `abspath` 标记的项目 | 不移动，写入 `.agents/adopted.txt` 并在目录内建 `CONTEXT.md`；不改目录内已有的规则和说明文件 |
| 缓存 | `cache` 标记的目录，以及其他可重建的依赖或下载缓存 | 不建主题，不移动，保留在白名单中；在交付报告中列出体积，是否删除由用户决定 |
| 暂不处理 | 用户点名不动的内容、用途无法确认的内容 | 留在原位，保留在白名单中，列入交付报告 |

带 `abspath` 标记的条目移动后，写死的路径会失效。只有用户明确要求时才把它列入移动，并在计划摘要中写出受影响的文件。

默认做法：

- 按“同一项目、目标或交付物”分组，不按文件类型分组。零散文件按名称和日期归到所属的事情上，确实无法归属的集中到一个“未分类”主题。
- 整个目录一起移动，不拆散内部结构，不改文件名和目录内部的名称。
- 主题目录的日期使用 `scan` 给出的最近修改日期，名称按工作区的命名规则。
- “原地保留”是建议而不是禁令：多数 AI 客户端按工作目录保存会话，这类目录移动后原会话可能不再显示。把这一点告诉用户，由用户决定。
- 工作区根目录本身不改名；不移动 `AGENTS.md`、`README.md`、`.agents/`、`.git/` 和各客户端的配置目录。

把计划写入 `.agents/move-plan.tsv`，每行一项，路径相对工作区根：

```text
原路径<TAB>新路径
```

然后向用户展示摘要：将建立的主题及各自包含的条目数、原地保留的目录及其标记、缓存目录、暂不处理的条目、拿不准的归类、疑似重复或无用的文件，以及每个主题拟定的状态。状态拿不准的主题单独列出，询问用户是否仍在使用。条目很多时展示摘要并指向计划文件，不逐行复述。

### 4. 校验与确认

```text
python .agents/tools/workspace_doctor.py move --plan .agents/move-plan.tsv
```

校验只读。有问题时修正计划后重新校验。通过后等待用户明确同意；用户要求调整时修改计划并重新校验。

### 5. 执行

```text
python .agents/tools/workspace_doctor.py move --plan .agents/move-plan.tsv --apply
```

- 脚本中途失败时会停止并保留已完成部分的记录；报告给用户，不用其他方式继续移动。
- 为每个新主题写入口 `CONTEXT.md`：`title`、`status`、`updated`，并把原目录名或原文件名中的关键词写进 `aliases`，方便按旧名称找到。状态以用户在第 4 步的答复为准：仍在使用的用 `active`，暂时不用的用 `paused`，已结束的用 `done`。用户没有说明时，`scan` 的最近修改日期只作参考：近一个月内修改过的用 `active`，其余用 `paused`；修改日期不代表是否仍在使用，所以要在交付报告中列出这样推定的主题。目标、主要产物和下一步只写能从清单确定的内容，不编造。
- 原地保留的目录按工作区内 `.agents/maintenance.md` 的“登记老目录”处理。
- 运行 `index --write` 和 `check`。

### 6. 验证与交付

- `check` 无错误；用 `where` 抽查几个原路径，确认能查到现在的位置。
- 运行 `scan work`，检查被移动的主题是否带 `abspath` 标记。有标记时，只读取标出文件中含路径的那几行，区分两种情况：日志或记录中的历史路径，列入报告即可；脚本、配置中实际使用的路径，列出“文件、旧路径、建议的新路径”，经用户同意后再修改，或用 `move --undo` 撤销。
- `scan` 确认根目录只剩管理文件、原地保留的目录和暂不处理的条目。
- 向用户报告：建立的主题数量、移动的条目数量和批次、原地保留、缓存与暂不处理的清单、按修改日期推定状态的主题、读取过内容的用户文件清单、未能验证的事项。
- 告诉用户：
  - 不满意时可以运行 `python .agents/tools/workspace_doctor.py move --undo` 撤销这一批；撤销后需重新生成索引。
  - 继续整理之前的旧对话时，先在那个对话里说：“这是整理前的旧对话，请先读 `.agents/old-chats.md`。”
  - 之后的新对话照常使用，不需要任何额外说明。

## 旧对话怎么继续

旧对话指整理之前产生的对话，它的历史里记的是整理前的路径。由你在该对话中说明，AI 不自行判定。

说明之后，AI 按工作区内的 `.agents/old-chats.md` 处理：

1. 用 `where` 把历史中的路径换算成现在的位置，读取文件所属主题的入口。
2. 在现在的位置继续工作，并利用它掌握的背景补全主题入口。
3. 发现相关文件被分到几个主题时，优先在入口中互相加链接。
4. 确需移动时，列出“现路径 → 新路径”和理由，得到你在该对话中的同意后才用 `move` 执行；授权只覆盖列出的条目。

没有说明的旧对话仍然能工作：根规则要求路径找不到文件时先用 `where` 查询，不重建文件；但它不会主动补全入口或提出移动。

客户端是否在恢复旧对话时重新加载根规则，取决于客户端，本 Kit 没有逐个验证。规则没有重新加载时，上面那句说明同样有效，因为它让 AI 直接去读 `.agents/old-chats.md`。

## 上下文占用

| 内容 | 何时进入上下文 | 大小（约） |
| --- | --- | --- |
| 根 `AGENTS.md` 的 Kit 区块 | 每次对话，由客户端加载 | 1.6 KB |
| `.agents/workspace.md` 与 `.agents/local.md` | 对话中首次落盘前 | 4.5 KB + 本地规则 |
| `.agents/maintenance.md` | 整理、登记老目录、归档、记录决定、处理检查错误时 | 5.8 KB |
| `.agents/old-chats.md` | 用户说明是旧对话时 | 2.2 KB |
| `find`、`where` 的结果 | 查找主题或旧路径时 | 每项一到两行 |
| 根 README 的主题索引、`.agents/moves.tsv` | 不直接读取，由脚本查询 | 不进入上下文 |
| 本文与安装协议 | 仅在整理、安装或升级时 | 不写入工作区 |

纯问答的对话只承担第一行。移动记录再长也只通过 `where` 查询，不会被整份读入。

## 整理后验收

| 你说 | 期望行为 |
| --- | --- |
| “整理一下这个工作区。” | 清点、给出计划摘要并等待确认；确认前不移动任何内容。 |
| “`某个旧路径` 现在在哪？” | 运行 `where`，给出现在的位置。 |
| （整理后新开的对话，隔天继续）“接着做。” | 按普通流程在原主题继续，不读取 `.agents/old-chats.md`。 |
| （整理前的对话，未作说明）“打开之前那个文件。” | 路径失效时先用 `where` 查询，在新位置读取，不重建文件，不移动。 |
| （整理前的对话）“这是整理前的旧对话，请先读 `.agents/old-chats.md`。” | 查询历史路径的现位置，读取所属主题入口，在新位置继续。 |
| （同一个旧对话）“这些文件应该放在一起。” | 列出“现路径 → 新路径”和理由，得到同意后才用 `move` 执行。 |
| “撤销刚才的整理。” | 运行 `move --undo`，再重新生成索引并检查。 |
