# 维护约定

本文件由 [工作区操作约定](workspace.md) 按需引用，日常保存文件不需要读它。只读与当前任务对应的一节。

## 登记老目录

老目录指不在 `work/` 和 `archive/` 内的已有目录。登记让它保持原位又能被 `find` 和索引找到，适合不宜移动的目录：Git 仓库、被 AI 客户端单独打开过的项目、带绝对路径依赖的环境。

何时登记：整理计划中决定原地保留，新聊天接手并会持续在其中工作，或用户要求。只读取或零星修改时不登记。

1. 在 `.agents/adopted.txt` 追加一行该目录相对工作区根的路径（如 `old-project` 或 `projects/api`）。文件不存在时创建；每行一个路径，空行和 `#` 开头的行忽略。
2. 目录内没有 `CONTEXT.md` 时新建，按主题入口格式写 front matter、目标、主要产物和下一步。已有 `CONTEXT.md` 但不是主题入口时，先询问用户再改。不改已有的 `README.md`。
3. 写入口只读必要信息：目录的顶层列表和已有说明文件。不通读全部文件；标题和别名拿不准时使用目录名并询问用户。
4. 老目录是 Git 仓库时，入口是新增的未跟踪文件：不提交，不改该仓库的 `.gitignore`，除非用户要求。
5. 运行 `index --write` 和 `check`。

登记后的主题 `status` 不使用 `archived`。目录被用户移走或删除时，`check` 会报 `adopted_missing`，按实际情况更新或删除对应行。

## 整理与移动已有内容

只在用户主动要求时进行。整理整个老工作区时，按 AI Workspace Kit 仓库的“整理已有工作区”协议（`docs/reorganize.md`）执行；用户只点名少量条目时按本节处理。

1. 清点：`python .agents/tools/workspace_doctor.py scan`，条目多时加 `--limit <N>`；看不出用途的目录用 `scan <子目录>` 看下一层。只在名称无法判断时读取少量文件的开头，不通读。是否写死绝对路径以 `abspath` 标记为准，不自行全文搜索。配置、密钥、会话类文件只按名称判断，不打开。
2. 计划：把“原路径 → 新路径”逐行写入 `.agents/move-plan.tsv`（每行 `原路径<TAB>新路径`，相对工作区根）。整个目录一起移动，不拆散内部结构，不改文件名。向用户说明归类依据和拿不准的条目。
3. 确认：运行 `move --plan .agents/move-plan.tsv` 校验，等用户明确同意。
4. 执行：加 `--apply`。脚本不覆盖已有目标，并把每项移动写入 `.agents/moves.tsv`；`move --undo` 撤销最近一批。
5. 收尾：为新主题写入口（别名中保留原目录名），更新 `.agents/adopted.txt` 和受影响的链接，运行 `index --write` 和 `check`。再用 `scan work` 查看被移动的主题是否带 `abspath` 标记；脚本或配置中实际使用的旧路径，经用户同意后修改，或撤销移动。

以下目录默认建议原地保留并登记，移动前必须向用户说明后果：

- 带 `agent` 标记的嵌套工作区和技能目录，以及 Git 仓库：多数 AI 客户端按工作目录保存会话，技能也常按绝对路径加载，移动后原会话可能不再显示。
- 带 `env` 或 `abspath` 标记的目录：虚拟环境和写死的绝对路径移动后会失效。

带 `cache` 标记的缓存目录不建主题、不移动，是否删除由用户决定。主题状态不只看修改日期，拿不准时问用户是否仍在使用。

工作区根目录本身不改名。不删除文件：重复或疑似无用的内容只列出，由用户决定。

## 归档

- 用户明确要求归档时，把整个主题移到 `archive/`，`status` 改为 `archived`，保留内部结构；目标重名时先检查，不覆盖。
- 归档已登记的老目录属于移动：先按上一节说明后果，用 `move` 执行，再从 `.agents/adopted.txt` 删除该行。
- 同步主题入口、根索引和受影响的相对链接。
- 整理或归档不默认授权删除、覆盖或批量移动其他主题。

- `index --write` 只替换标记区块；索引表含主题、入口、状态、标签四列，按状态、再按标题排序。
- `check` 检查根目录、主题入口、元数据、登记路径、重复标题或别名和相对链接。
- `find` 匹配标题、别名、标签、目录名或登记路径；多个关键词按空白拆分且全部命中才匹配，整句精确匹配优先。
- `scan [<子目录>]` 列出根目录（或子目录）中的条目及其文件数、体积、最近修改日期和标记（`git`、`project`、`agent`、`env`、`cache`、`abspath`）；绝对路径只在脚本内部比对，输出文件名不输出内容；`scan --write-allowlist` 把未登记的根目录条目追加到 `.agents/root-allowlist.txt`，不移动任何内容。
- `where <路径>...` 按 `.agents/moves.tsv` 把旧路径换算成现在的位置；`move` 的用法见“整理与移动已有内容”。
- 出现元数据错误时先修正入口，再生成索引；有错误的主题不进入索引。
- 根目录出现未登记条目时，先确认它是否是本次任务误放的产物：是则移入所属主题，属于用户内容则经用户同意后记入白名单。
- 脚本不可用时：读取根 [主题索引](../README.md#主题索引)，列出 `work/`、`archive/` 的直接子目录和 `.agents/adopted.txt`，只打开可能相关主题的入口；按入口元数据手工维护同一索引区块，不建第二份清单，并说明未运行脚本检查。

## 记录决定

- 只有影响后续工作的实质决定才单独记录；普通修改和每轮聊天不记录。查到相关记录时优先更新已有内容。
- 主题决定放在主题 `notes/`，工作区管理决定放在 `.agents/notes/`；不预建空目录。
- 写明问题、采用方案、真实考虑过的替代方案、后果和验证；不复制完整聊天。
- 事实变化时同步路径和状态；旧结论被取代时写明取代关系，不把未实施的建议写成已完成事实。
- 项目专属规则放项目自己的规则入口，不追加到根 `AGENTS.md`。嵌套项目若会被单独打开，在它自己的规则入口说明需要继承的工作区规则。
