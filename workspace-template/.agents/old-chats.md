# 旧对话接续

本文件只在用户说明“本聊天开始于工作区整理之前”时读取。旧对话指这一种：它产生于整理之前，历史里记的是整理前的路径。

- 是否属于旧对话由用户说明，AI 不自行判定，也不因为隔天、换窗口或路径对不上而套用本文件。整理之后才开始的聊天始终按 [工作区操作约定](workspace.md) 处理。
- `.agents/moves.tsv` 不存在时，工作区没有做过整理，告诉用户并按普通流程继续。

## 找回文件

1. 把本聊天历史中用到的路径交给脚本查询，可一次传多个（解释器依次尝试 `python3`、`python`、`py -3`）：

   ```text
   python .agents/tools/workspace_doctor.py where <旧路径> [<旧路径> ...]
   ```

2. 查不到记录且文件不存在时，用 `find <关键词>` 找可能的主题；仍找不到就询问用户。不重建文件，不凭猜测选用同名文件。
3. 读取文件现在所属主题的入口，了解整理后的归属。

## 继续工作

- 在文件现在的位置继续读写，新产物放进它现在所属的主题。不把文件搬回旧位置，也不在旧位置重建目录。
- 利用本聊天掌握的背景补全相关主题的入口（目标、别名、主要产物、下一步），并告诉用户改了什么。这属于内容修改，不需要移动授权。
- 本聊天的文件分散在几个主题时，优先在入口中互相加链接，不移动。

## 需要移动时

只有不移动就无法继续工作，或归类明显错误时才提出移动，并且必须在本聊天中得到用户授权：

1. 列出现状和建议：每一项的“现路径 → 新路径”和理由。
2. 用户明确同意后，把这些条目写成计划文件，运行 `python .agents/tools/workspace_doctor.py move --plan <计划文件>` 校验，再加 `--apply` 执行。不用其他方式移动，以保证移动记录完整。
3. 授权只覆盖列出的条目；不顺带整理其他内容。
4. 移动后更新受影响的主题入口、`.agents/adopted.txt` 和索引（`index --write`、`check`）。

不删除文件；认为多余的文件只列出并交给用户决定。
