# 工作区操作约定

本文件由根目录 [AGENTS.md](../AGENTS.md) 按需引用。除明确标注为硬规则的内容外，以下各节都是默认做法；项目已有且更具体的惯例可以覆盖默认做法。

## 硬规则补充

- 主题入口的 front matter 必须能被标准库脚本解析，不使用本约定未列出的 YAML 语法。
- 根 README 索引标记区块在脚本可用时只能由 `index --write` 生成，不手工编辑；只有脚本不可用时才手工维护同一区块。

## 确定主题

保存文件前按以下顺序判断：

1. 用户指定位置，或本聊天已确定的主题。
2. 能运行脚本时，执行 `python .agents/tools/workspace_doctor.py find <关键词>`（解释器按下方顺序尝试）；可多次使用用户原话中的关键词。
3. 脚本不可用时，读取根 [主题索引](../README.md#主题索引)，并列出 `work/` 和 `archive/` 的直接子目录；只打开可能相关主题的入口。
4. 只有延续同一项目、目标或交付物时才复用；宽泛关键词相同不构成复用理由。
5. 候选结果对已有内容有实质影响且无法区分时，询问用户。

默认新建 `work/YYYY-MM-DD-简短主题/`。日期使用用户指定时区；未指定时使用当前执行环境的当地日期。主题名用简短中文或英文，以 `-` 连接词语，避免空白、`/ \ : * ? " < > |` 和过长名称。确属独立主题且重名时追加 `-02` 等后缀；创建前再次检查，禁止覆盖。

换窗口、跨天、重试或启动子代理不构成另建目录的理由。首次确定或改变目录时告知实际路径。命令的工作目录和输出路径指向主题；远程或工作区外产物记录真实位置。

## 主题入口

每个主题位于 `work/<目录名>/` 或 `archive/<目录名>/`，只识别这两层下的直接子目录。

入口文件选择：

- 主题根目录存在 `CONTEXT.md` 时使用它。
- 否则使用 `README.md`。
- 已有项目的 `README.md` 承担项目说明时，不改其用途，新建 `CONTEXT.md` 作为主题入口。

入口顶部使用 YAML front matter。为便于标准库解析，只允许以下简单格式：

```markdown
---
title: Linux 命令学习
aliases: [shell 学习, Linux 笔记]
tags: [linux, 学习]
status: active
updated: 2026-11-05
---

# Linux 命令学习

- 目标：
- 主要产物：
- 下一步：
```

| 字段 | 必需 | 规则 |
| --- | --- | --- |
| `title` | 是 | 非空字符串 |
| `aliases` | 否 | 行内列表，默认空列表 |
| `tags` | 否 | 行内列表，默认空列表 |
| `status` | 是 | `active`、`paused`、`done`、`archived` 之一 |
| `updated` | 是 | `YYYY-MM-DD` |

- `work/` 中的主题不能是 `archived`；`archive/` 中的主题必须是 `archived`。
- 状态在人类可读位置的中文对应：`active` 进行中、`paused` 暂停、`done` 已完成、`archived` 已归档。
- 创建入口时填写 `title`、`status: active`、`updated`，并加入用户可能使用的别名和少量标签。
- 有实质产出或状态变化时更新 `updated`，不因阅读或格式整理更新。
- 有实质产出后更新目标、主要产物链接、必要约束和下一步。
- 简单主题可以把正文直接写在入口文件中；正文较长或有多个产物时，入口只保留目标、状态、摘要和产物链接，正文另存为独立文件。

嵌套项目若会被单独打开，在项目自己的规则入口说明需要继承的工作区规则。

## 放置产物

- 默认把普通文档、图片、下载、脚本、依赖和日志放进所属主题；根目录只保留工作区管理文件。
- 简单主题先建入口和实际产物；内容增多后按需增加 `inputs/`、`outputs/`、`src/`、`notes/`、`tmp/`，代码项目沿用自身布局。
- 用户原件保留，副本和结果放主题内。外部工具生成的最终结果在可行且获授权时复制到主题并记录来源；否则记录真实位置。
- `inbox/` 是用户可选的投放区，不预建；AI 不把自己的产物放进去，只有用户要求时才整理。
- 依赖、虚拟环境、下载缓存、模型文件等可重建的大文件放在所属主题中工具惯用的位置或 `.cache/`；工作区受 Git 或同步工具管理时，经用户同意后加入忽略规则。
- 安装前已存在的根目录内容记录在 `.agents/root-allowlist.txt`，保持原位，用户要求时再整理。
- 需要保留多个版本时使用清晰版本号或时间标识，不用 `final-final` 一类名称。

- 出现元数据错误时先修正入口，再生成索引；不要让有错误的主题进入索引。
- 修改共享入口前重新读取最新内容，只改相关部分，保留其他聊天新增的内容。

## 记录决定

- 只有影响后续工作的实质决定才单独记录；普通修改和每轮聊天不记录。查到相关记录时优先更新已有内容。
- 主题决定放在主题 `notes/`，工作区管理决定放在 `.agents/notes/`；不预建空目录或多层分类。
- 写明问题、采用方案、真实考虑的替代方案、后果和验证；不复制完整聊天或重复文件清单。
- 事实变化时同步路径和状态；旧结论被取代时写明取代关系，不把未实施建议写成已完成事实。
- 项目专属规则放项目自己的规则入口，不追加到根 `AGENTS.md`。

## 归档

- 完成主题只把 `status` 改为 `done`，目录保持原位。
- 用户明确要求归档时，把整个主题移到 `archive/`，`status` 改为 `archived`，保留内部结构；目标重名时先检查，不覆盖。
- 同步主题入口、根索引和受影响的相对链接。
- 整理或归档不默认授权删除、覆盖或批量移动其他主题。

## 结束前检查

确认产物能从主题入口找到，入口元数据与实际文件一致，根索引已更新且 `check` 无错误，根目录没有本次遗留的普通产物。向用户提供真实交付位置，并说明未完成的验证。
