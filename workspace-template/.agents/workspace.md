# 工作区操作约定

本文件由根目录 [AGENTS.md](../AGENTS.md) 引用，首次落盘前读取。除标注为硬规则的内容外均为默认做法，项目已有且更具体的惯例可以覆盖。

只有在做以下事情时才读 [维护约定](maintenance.md)：整理或移动已有内容、登记老目录、归档、记录决定、处理检查错误、脚本不可用时手工维护索引。用户说明本聊天开始于工作区整理之前时，改读 [旧对话接续](old-chats.md)。

## 硬规则补充

- 主题入口的 front matter 必须能被标准库脚本解析，不使用本约定未列出的 YAML 语法。
- 根 README 索引标记区块在脚本可用时只能由 `index --write` 生成，不手工编辑。
- 整理、移动已有内容只在用户主动要求时进行，不因为内容不符合本约定而顺手整理；移动一律使用脚本的 `move` 命令，以留下移动记录。

## 确定主题

保存、下载、克隆仓库、安装依赖、编译生成文件等都属于落盘任务，执行前按以下顺序确定归属。用户只问“怎么用”时，阅读在线说明并回答，不扩展为克隆、安装或编译。

1. 用户指定的位置，或本聊天已经在使用的位置：沿用，到此为止。该位置的文件找不到时，运行 `python .agents/tools/workspace_doctor.py where <路径>` 查移动记录。
2. 运行 `python .agents/tools/workspace_doctor.py find <关键词>`（解释器依次尝试 `python3`、`python`、`py -3`），可多次使用用户原话中的关键词。脚本不可用时按维护约定手工查找。
3. 只有延续同一项目、目标或交付物时才复用；宽泛关键词相同不构成复用理由。
4. 任务属于某个尚未整理的老目录（不在 `work/` 和 `archive/` 内）时就地工作。新聊天接手并会持续使用它时，按维护约定“登记老目录”登记一次；只读取或零星修改不登记。
5. 候选对已有内容有实质影响且无法区分时，询问用户。

无匹配时新建 `work/YYYY-MM-DD-简短主题/`。日期使用用户指定时区，未指定时用执行环境的当地日期。主题名用简短中文或英文，以 `-` 连接，避免空白和 `/ \ : * ? " < > |`；重名追加 `-02` 等后缀，禁止覆盖。

换窗口、跨天、重试或启动子代理不构成另建目录的理由。首次确定或改变目录时告知实际路径；命令的工作目录和输出路径指向主题。

## 主题入口

主题是 `work/`、`archive/` 的直接子目录，或 `.agents/adopted.txt` 中登记的老目录。入口是主题根目录的 `CONTEXT.md`，没有时用 `README.md`；`README.md` 已承担项目说明时，新建 `CONTEXT.md`。

```markdown
---
title: Linux 命令学习
aliases: [shell 学习, Linux 笔记]
tags: [linux, 学习]
status: active
updated: 2026-11-05
---

# Linux 命令学习

- 目标：
- 主要产物：
- 下一步：
```

- `title`、`status`、`updated`（`YYYY-MM-DD`）必需；`aliases`、`tags` 是可省略的行内列表。
- `status` 取 `active`、`paused`、`done`、`archived`。只有 `archive/` 中的主题是 `archived`，且必须是。
- 创建时写入用户可能使用的别名和少量标签。有实质产出或状态变化时更新 `updated`、目标、产物链接和下一步；阅读或格式整理不更新。
- 正文较长或有多个产物时，入口只留目标、摘要和产物链接，正文另存。
- 完成主题只把 `status` 改为 `done`，目录保持原位。

## 放置产物

- 文档、图片、下载、脚本、依赖和日志都放进所属主题；根目录只保留工作区管理文件。
- 简单主题只要入口和实际产物；内容增多后按需增加 `inputs/`、`outputs/`、`src/`、`notes/`、`tmp/`，代码项目沿用自身布局。
- 用户原件保留，副本和结果放主题内；工作区外的产物记录真实位置。
- `inbox/` 是用户的投放区，AI 不把自己的产物放进去。
- 可重建的大文件放在工具惯用位置或 `.cache/`。多个版本用清晰的版本号或时间标识。
- 修改共享入口前重新读取最新内容，只改相关部分。

## 结束前

主题创建、移动或状态变化后运行 `python .agents/tools/workspace_doctor.py index --write`，再运行 `check`。确认产物能从入口找到、根目录没有本次遗留的产物，向用户提供真实交付位置并说明未完成的验证。检查报错时按维护约定处理。
